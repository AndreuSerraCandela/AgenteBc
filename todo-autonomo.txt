Contexto
--------
Producto distinto del flujo consultor (agentebc-desktop / “Ejecutar acción y
diagnosticar”). Un servicio autónomo registra facturas (y otros tipos en el
futuro) según criterios o programación; solo cuando hay error (o casos dudosos)
invoca AgenteBc. AgenteBc diagnostica, intenta remedio acotado si existe, o
escala a un consultor humano.

Hoy AgenteBc:
- Automatiza 1 documento × 1 acción (Playwright: web_preview.py).
- Diagnostica sin modificar “por diagnóstico” (diagnosis.py → ProposedSolution
  orientadas a revisión humana).
- Buzón /inbox = recetas compartidas entre consultores (action_share), NO
  cola de fallos de registro.
- No hay listado OData por fechas, colas, scheduler ni API unificada de incidentes.

Visión (dos piezas)
-------------------
  [Worker autónomo]                    [AgenteBc motor]
  Cola / cron → OData list → Registrar → OK → fin
                              ↓ error
                         Incident JSON → diagnose (+ IA opcional)
                              ↓
                    ¿Remedio en catálogo + confianza alta?
                         sí → acción correctiva → reintento (límite N)
                         no → escalar consultor (nueva cola de casos)

Idea de arquitectura (detalle)
------------------------------
  Criterios (fechas, empresa, tipo doc) — manual, DSL @menciones o job JSON
       → DocumentReader.list_* (NUEVO: $filter OData, p. ej. postingDate)
       → BusinessCentralWebPreview.run por documento (misma receta JSON)
       → Estado por doc: pending | running | posted | failed | remediating | escalated

  Fallo → Incident (models.py) + PreviewMessage + screenshot + metadata
       → DiagnosticService + enrichments (+ Jev triaje cuando exista: todo.txt)
       → Política de cierre (NUEVO): auto_remediate | retry | escalate
