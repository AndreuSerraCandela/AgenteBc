Contexto
--------
Jev es un modelo "System One" (TypeSafe): no genera informes en prosa; devuelve
decisiones tipadas con probabilidades (choice, noul, score) sobre un "state"
que enviamos. API vía OpenRouter Decisions (p. ej. typesafe/jev-1.13).
Docs: https://jevai.dev/es/
      https://openrouter.ai/docs/guides/community/jev-tutorial

AgenteBc hoy usa LLM generativos para conclusiones (lm_studio, deepseek API,
deepseek_web, google_ai_web) en llm_conclusions.py — prompt largo → texto en
español (causa, pasos, confianza, etc.). Jev NO sustituye eso; complementa.

Idea de arquitectura
--------------------
  Error BC + evidencia (PreviewMessage, DiagnosticReport, enrichments)
       → Jev: 2–5 preguntas tipadas en una sola llamada
       → Python: umbrales de probabilidad + reglas de negocio
       → Si hace falta informe para el consultor → request_ai_conclusion (LLM actual)

Casos de uso candidatos en AgenteBc

[ ] Pre-check acciones interactive: ¿contexto encaja con la receta? (extra a reglas)
